# 格式规范

AIX 是一种结构化应用包格式。它把应用配置、页面实现、资源和机器可读的数据约定放入同一个 `.aix` 产物，使其既能作为文件分发，也能被工具直接分析。

## 设计目标

AIX 关注三个目标：

- **可分发**：应用及其页面资源可以作为单一文件传输和保存。
- **可检查**：包内条目、元数据、页面和 schema 无需运行应用即可读取。
- **可派生**：读取方可以根据页面 schema、布局和目标信息生成结构化工具界面。

包是唯一事实来源。CLI、Rust 库和浏览器工具只是同一份包模型的不同读取入口。

## 典型包结构

```text
.
├── AGENTS.md
├── VERSION
├── app.json
├── app.js
├── pages/
└── META-INF/
    └── aix/
        ├── manifest.json
        ├── public-key.ed25519    # 仅签名包包含
        └── signature.ed25519     # 仅签名包包含
```

主要条目的职责如下：

- `AGENTS.md`：描述智能体身份、能力和上下文。
- `app.json`：保存应用级元数据、页面路由和源目录中的引擎要求。
- `app.js`：应用运行入口。
- `pages/`：保存页面定义、资源和带 schema 的文件。
- `VERSION`：供旧版提取缓存使用的构建 ID。
- `META-INF/aix/manifest.json`：保存构建 ID、内容派生的包 ID、引擎范围、文件大小和 SHA-256 摘要。

`manifest.version` 会镜像 `VERSION` 以保持兼容。新运行时应优先使用 `manifest.package_id` 识别内容，同时为旧包保留 `VERSION` 回退逻辑。

## 页面与工具

页面不仅是视图。读取方可以从页面中获取：

- 页面路径、标题和尺寸
- 页面级数据 schema
- 布局与目标提示
- 根据 schema 推导出的工具名称、参数和目标

这使页面同时具备可视界面和结构化工具入口两种用途。没有 schema 的页面仍可正常作为页面读取，但无法提供同等完整的工具参数约定。

## 读取顺序

建议按以下顺序理解和处理 AIX 包：

1. 打开归档并枚举具体条目。
2. 读取清单，确认包身份、文件摘要和引擎兼容范围。
3. 读取 `app.json`，解析应用元数据和页面路由。
4. 加载页面定义及其 schema、布局和目标信息。
5. 按需生成页面列表、检查界面或结构化工具定义。

## 引擎兼容性

打包后的运行时兼容范围以 `META-INF/aix/manifest.json` 为准。创建包时，CLI 按以下顺序确定范围：

1. `aix pack --engine` 显式传入的范围
2. `app.json.engine`
3. 默认值 `*`

常见范围包括精确版本 `0.14.0`、最低版本 `>=0.14.0` 和兼容范围 `^0.14.0`。目录预览可以直接读取源目录，但已打包产物不再以 `app.json.engine` 作为运行时兼容性来源。

## 实现入口

- `crates/aix`：读取和分析包
- `crates/aix-pack`：构建、规范化和优化包
- `crates/aix-cli`：原生 Rust CLI
- `packages/cli`：基于同一 WASM 引擎的 npm CLI
- `crates/aix-web`：浏览器和 TypeScript 读取接口
